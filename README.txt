# Property Data Reconciliation Agent: HMLR–EPC Conflict Detection and Resolution

This project implements a **Property Data Reconciliation Agent** for identifying and resolving inconsistencies between **HM Land Registry (HMLR) Price Paid Data** and **Energy Performance Certificate (EPC) data**.

The agent reconciles matched property records across three main areas:

1. **Property Type** — HMLR Property Type vs EPC Property Type
2. **Built Form** — HMLR Property Type vs EPC Built Form
3. **Construction Age / New-Build Status** — HMLR Old/New vs EPC Construction Age Band and Transaction Type

The system uses rule-based evidence from property attributes, neighbouring properties, transaction history, and EPC information to identify conflicts and determine the most appropriate source to follow.

## 2. Dataset Preparation

Before running the agent, download the required datasets and place them in the `data/` directory.

### 2.1 HM Land Registry Price Paid Data

Download the **2026 yearly CSV file** from the official HM Land Registry Price Paid Data page:

[HM Land Registry — Price Paid Data Downloads](https://www.gov.uk/government/statistical-data-sets/price-paid-data-downloads?utm_source=chatgpt.com)

* Use the **2026 yearly data**.

The yearly files contain standard and additional Price Paid Data transactions for the relevant calendar year.

### 2.2 Energy Performance Certificate (EPC) Data

Download the **Domestic EPC bulk data** from the official government service:

[Get Energy Performance of Buildings Data](https://get-energy-performance-data.communities.gov.uk/?utm_source=chatgpt.com)

Select the **Domestic** EPC data.

The official service provides bulk EPC certificate data in CSV format for domestic and non-domestic properties in England and Wales. A GOV.UK One Login account is required to access the bulk downloads.

* Use **Domestic EPC data only**
* Retain EPC records from **January 2026 onwards**

The EPC data covers certificates registered since 2012 and includes both existing and new domestic dwellings.

### 2.3 Data Directory

After downloading the datasets, the `data/` directory should contain the required input files, for example:

```text
data/
├── pp-2026.csv
└── epc-2026.csv
```

# 5. Run the Property Data Reconciliation Agent

The interactive reconciliation agent can be started with:

```bash
python reconciliation_engine.py
```

The agent will prompt for a postcode:

```text
Enter postcode (e.g. CM7 1XF):
```

### Step 1 — Enter a postcode

Enter the postcode of the property you want to investigate.

If no matching record is found:

```text
No records found for this postcode.
```

### Step 2 — Select an address

If multiple addresses are associated with the postcode, the agent displays the available addresses and asks the user to select one.

```text
Found multiple addresses under this postcode:

1. ...
2. ...
3. ...

Select an address (enter number):
```

### Step 3 — Select a transaction

If the selected address has multiple matched transaction/inspection records, the agent displays the available records and asks the user to select the relevant transaction.

```text
Found X transactions for this address:

1. transaction_id=...
2. transaction_id=...
3. transaction_id=...

Select a transaction (enter number):
```

### Step 4 — Reconciliation Results

The selected property is then evaluated against the three conflict categories:

```text
[Property_Type]
[Built_Form]
[Construction_Age]
```

For each category, the agent reports:

* HMLR value
* EPC value
* Whether a conflict was detected
* Which source is followed
* The evidence/reason for the decision

The user can then search for another property or exit the agent.

# 6. Conflict Detection and Resolution Rules

The reconciliation engine evaluates three types of conflicts.

## Conflict 1 — Property Type

**HMLR Property Type vs EPC Property Type**

This conflict concerns whether the transaction represents a whole dwelling or a subdivided unit:

* House / Bungalow
* Flat / Maisonette

### Rule 1 — Flat/Maisonette Evidence

Evidence from:

* `"FLAT"` in the address
* Letter-suffixed house number
* EPC floor-level information

These provide strong evidence for a Flat/Maisonette classification.

**Example postcodes:**

```text
RG14 5RG
BN1 1YD
```

### Rule 2 — Quantile-based Property-Type Scoring

Floor area and number of habitable rooms are used as supporting evidence.

The result is classified as:

```text
Flat-like
House-like
Ambiguous
```

**Example postcode:**

```text
W6 9RL
```

### Rule 3 — Ambiguous / Insufficient Evidence

When the available independent evidence is insufficient or ambiguous, HMLR is retained as the fallback source.

**Example postcode:**

```text
N5 1FP
```

---

## Conflict 2 — Built Form

**HMLR Property Type vs EPC Built Form**

Built form describes the physical attachment of the building:

* Detached
* Semi-Detached
* Mid-Terrace
* End-Terrace

### Rule 1 — Neighbouring Built Form

The majority built form among nearby properties on the same street is used as independent supporting evidence.

The neighbouring properties are searched within the relevant house-number range, and a majority of at least 50% is treated as sufficiently strong supporting evidence.

**Example postcode:**

```text
S6 4LU
```

### Rule 2 — HMLR-Supported Built Form

When the neighbouring properties support the HMLR classification rather than the EPC classification, HMLR is retained.

**Example postcode:**

```text
LE3 2FL
```

---

## Conflict 3 — Construction Age / New-Build Status

**HMLR Old/New vs EPC Construction Age Band**

This conflict considers:

* HMLR Old/New status
* EPC Construction Age Band
* EPC Transaction Type
* Prior HMLR transaction history

The rules distinguish between strong and weak evidence for a new-build classification.

### Rule 1 — Strong New-Build Evidence

An EPC record indicating:

```text
Transaction Type = New dwelling
Construction Age Band = 2026
```

combined with no earlier HMLR transaction provides strong evidence that the property may be expected to have an HMLR New (`Y`) classification.

### Rule 2 — Prior Transaction Evidence

If an earlier HMLR transaction exists for the same property, the EPC `"New dwelling"` classification is treated as conflicting evidence, and HMLR is retained.

### Rule 3 — Weak New-Build Evidence

A recent EPC Construction Age Band alone does not determine HMLR's Old/New classification.

Therefore, this situation is flagged as a **weak conflict warning** rather than automatically changing the classification.

# 7. Run Conflict Analysis for All Matched Properties

Instead of manually entering postcodes, the project also provides a batch conflict-analysis script.

Run:

```bash
python find_conflicts.py
```

This processes **all matched properties** in:

```text
data/linked_properties.csv
```

and applies all three conflict-checking functions.

The script reports the total number of matched properties and conflicts for each category:

```text
Linked properties: ...
Total conflicts: ...

Property_Type conflicts: ...
Built_Form conflicts: ...
Construction_Age conflicts: ...
```

It then generates separate CSV reports for the three conflict categories.

### Output files

#### Conflict 1

```text
hmlr_property_type_vs_epc_property_type_conflicts.csv
```

Contains all detected HMLR vs EPC **Property Type** conflicts.

#### Conflict 2

```text
hmlr_property_type_vs_epc_built_form_conflicts.csv
```

Contains all detected **Built Form** conflicts.

#### Conflict 3

```text
hmlr_old_new_vs_epc_construction_age_conflicts.csv
```

Contains all detected **Construction Age / New-Build** conflicts and warnings.

# 8. Two Ways to Use the System

### Interactive property investigation

Use:

```bash
python reconciliation_engine.py
```

Recommended when you want to investigate a **specific property by postcode**, inspect its records, and see the reasoning behind the reconciliation.

### Batch conflict analysis

Use:

```bash
python find_conflicts.py
```

Recommended when you want to process **all matched properties** and generate CSV reports containing all detected conflicts.
